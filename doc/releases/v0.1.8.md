## Built to run for months

Fixes for long-run problems found by auditing v0.1.7 inside Offlog, each confirmed by running the v0.1.7 binary. Every fix was written test-first: the test failed on v0.1.7, and fails again with the fix deliberately broken. New tests also watch resources over time (disk, memory, open connections), not only correctness.

**Attachment bytes are files, not sled values.** In v0.1.7 they lived in sled: ~2.6× their size on disk, never given back; resident memory grew with every attachment byte until a restart; unreferenced bytes couldn't be freed even by `POST /{db}/_compact`; and `DELETE /{db}` left them readable on disk.
- One file per distinct content: `<data>/att/<db>/<sha256>`, written to a temp file, fsynced, renamed into place. sled keeps only the md5 index.
- Mark-and-sweep cleanup: anything referenced by a stored revision (conflict leaves included) stays, nothing younger than an hour is touched (`NYXDB_ATTACHMENT_GRACE_SECS`), and the write gate is held so no reference slips in. It runs shortly after startup, about daily when idle, and on `POST /{db}/_compact`.
- `DELETE /{db}` removes the database's attachment folder.
- Existing attachments move from sled to files in the background on first start. Resumable and safe to kill at any point; reads fall back to sled until each one has moved.
- Measured: 20 MB of attachments used 46 MB on disk, 108 MB after replacing them and 123 MB after deleting every doc; now ~20, ~20 and ~0 MB. 1 GB of attachments written and read back leaves memory flat at ~30 MB (v0.1.7: 100 → 330 MB for 300 MB).

**Connections no longer stay open forever.** A 30 s header timeout, a 120 s idle timeout (never cutting a request in progress, so longpolls and continuous feeds keep working), TCP keepalive, and a cap of 256 open connections. The `_changes` exemption from the request timeout now needs an authenticated GET.

**`GET /{db}` and `_all_docs` no longer read every document.** Counts and a winners index are kept in each write's transaction; `_all_docs` is a range scan that stops at `limit`. At 50,000 docs they were ~20× slower than at 2,500; now about the same.

**Startup is safer.**
- `credentials.json` is written atomically; if it exists but can't be parsed, startup exits 3 and leaves it alone (it used to be replaced by a new password, locking clients out).
- A damaged store exits 3 instead of starting empty. With no sled snapshot to check against — normal after a hard kill — v0.1.7 opened a damaged database file as an empty store, under a new server id, and wrote over it.

**Upgrading:** tested from the real v0.1.5 and v0.1.7 binaries, including two hard kills mid-migration. Nothing Offlog relies on changed: `_revisions` on reads, `_bulk_get`, `_revs_diff`, `_bulk_docs new_edits:false`, `_local` docs, attachment GET by name with its Content-Type, the `_changes` longpoll and heartbeat, the `GET /` uuid, and `NYXDB_ADDR` / `NYXDB_DATA` / `NYXDB_USER` / `NYXDB_PASSWORD`.

**Verified before release:** build with zero warnings, clippy clean, 45 unit tests, and 39 HTTP, PouchDB (8.0.1 and 9.0.0) and upgrade suites via `node test/run_all.js`, locally and in CI.

See `doc/changelog.md` for every change and its test.
